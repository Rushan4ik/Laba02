# streamstats

StreamStats — это консольная утилита на Python, предназначенная для быстрого анализа потоковых данных. Программа считывает логи из файлов форматов CSV или JSONL, валидирует каждое событие и формирует сводный отчет в формате JSON.
Ключевая особенность — построчное чтение, что позволяет обрабатывать файлы любого размера без риска переполнения оперативной памяти.

## Установка

Нужен Python 3.10 или новее.

```bash
pip install -e .
pip install pytest ruff
```

## Запуск

```bash
python -m streamstats analyze D:/a.jsonl C:/b.jsonl --format jsonl --output report.json
python -m streamstats analyze events.csv --format csv --skip-invalid
```

- `--format csv|jsonl` обязателен, все файлы в одном запуске должны быть одного формата.
- `--output` необязателен. Без него отчёт печатается в консоль.
- `--skip-invalid` пропускает некорректные строки вместо остановки.

## Формат входных данных

У каждого события должны быть поля `timestamp` (ISO 8601), `level` (`DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL`), `source` (непустая строка) и `message`.

Время без часового пояса считается UTC, время с поясом переводится в UTC.

CSV:

```csv
timestamp,level,source,message
2023-10-01T10:00:00Z,INFO,auth,User login
```

JSONL (одно событие на строку):

```json
{"timestamp": "2023-10-01T10:00:00Z", "level": "INFO", "source": "auth", "message": "User login"}
```

## Отчёт

```json
{
  "total_events": 6,
  "by_level": {"INFO": 2, "ERROR": 1, "WARNING": 1, "CRITICAL": 1, "DEBUG": 1},
  "by_source": {"auth": 2, "db": 2, "api": 1, "app": 1},
  "top_error_sources": [{"source": "db", "count": 2}],
  "first_timestamp": "2023-10-01T10:00:00+00:00",
  "last_timestamp": "2023-10-01T10:20:00+00:00",
  "skipped_lines": 3
}
```

| Ключ | Значение |
|---|---|
| `total_events` | Число корректных событий во всех файлах |
| `by_level` | Число событий каждого уровня |
| `by_source` | Число событий каждого источника |
| `top_error_sources` | До пяти источников с наибольшим числом событий `ERROR` и `CRITICAL` |
| `first_timestamp`, `last_timestamp` | Самая ранняя и самая поздняя метки (UTC); `null`, если событий нет |
| `skipped_lines` | Сколько некорректных строк пропущено (в обычном режиме всегда 0) |

`top_error_sources` считает только события `ERROR` и `CRITICAL`, не больше пяти источников. Для пустого файла `total_events` равен 0, а метки времени равны `null`.

## Некорректные строки

- **Обычный режим:** обработка останавливается на первой плохой строке, в stderr выводится файл и номер строки, код возврата `2`, отчёт не создаётся.
- **С `--skip-invalid`:** строка пропускается, в stderr пишется предупреждение, а число пропущенных строк попадает в `skipped_lines`.

### Коды возврата
 
| Код | Значение |
|---|---|
| `0` | Успех |
| `2` | Ошибка: некорректная строка (без `--skip-invalid`), неверный формат, файл не найден, неверные аргументы |

### Исключения
 
Все ошибки пакета наследуются от `StreamStatsError`:
 
```text
StreamStatsError
├── UnsupportedFormatError   неподдерживаемый формат
├── InvalidEventError        неверное событие
│   └── InvalidTimestampError  неверная временная метка
└── CliConfigError           ошибка конфигурации CLI
```

На границе CLI перехватываются только `StreamStatsError` и `OSError`; они превращаются в понятное сообщение и код `2`.

Поток данных:
 
```text
файл → parsers (строка → Event или ошибка) → __main__ (решает: стоп или пропуск)
     → analysis.Analyzer (подсчёт) → report (dict → JSON)
```
 
## Как это устроено
 
- **Построчное чтение.** Парсеры это генераторы: они отдают по одной записи и не используют `read()` и `readlines()`. Память расходуется только на счётчики (по числу разных уровней и источников), а не на события.
- **Ошибки как значения.** Парсер не бросает исключение на плохой строке (оно бы остановило генератор навсегда), а отдаёт ошибку вместе с номером строки. Решение «остановиться или пропустить» принимается в одном месте, в `__main__`.
- **Единое время.** Все метки приводятся к UTC, иначе даты с поясом и без нельзя сравнивать.
- **Реестр парсеров.** Словарь `PARSERS` связывает имя формата с функцией. Неизвестный формат даёт `UnsupportedFormatError`.
- **Объединение файлов.** Один объект `Analyzer` последовательно получает события из всех файлов, отдельного слияния не требуется.
